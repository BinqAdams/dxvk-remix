# PKRTX changes to dxvk-remix

This fork (`pk-integration`) carries Painkiller-RTX-specific renderer + bridge changes on top of
NVIDIA's dxvk-remix. Newest first; folded into the unified PKRTX Steam build changelog.

## post-0.4.0 - 2026-07-28  (pk-integration @ 2360c7c6, rebased onto upstream main 09b20f1a)
- Fix orphaned GraphInstance use-after-free at scene clear (upstream PR candidate): PrimInstanceOwner::setReplacementInstance stored the back-pointer unconditionally while the prim-table slot write was bounds-guarded, so linking at an index beyond prims.size() made a one-way link the ReplacementInstance's clear() could never unlink. Reachable via processReplacementGraphs when every mesh prim of a graph-carrying replacement defers on its first frame (rtx.materializationBudgetTrianglesPerFrame): setup() has not sized the table, the env-conf graph one-way links, next frame's setup() wipes the table and a second graph links properly, and the orphan's dtor later reads the freed ReplacementInstance at level exit (SceneManager::clear -> GraphManager::clear). Crashed the SHIPPED 0.4.0 on Bridge exit (dump NvRemixBridge.exe_20260728_093936.dmp; deferral marker "Light prims anchored to a mesh replacement..." 35s prior on the same content). Fix: setReplacementInstance refuses unrepresentable links (assert + store null) and processReplacementGraphs skips graph creation until the replacement has a root, mirroring the light-prim guard. `patches/Painkiller/findings/steam-rc7-bridge-crash/`.
- Rebased the PK fork onto NVIDIA dxvk-remix `main` a08bc7f5 (+18 commits, from 2647ebfd): GPU crash recorder (b3612400: on-GPU-crash diagnostic dump to the log, hooks the submission queue and accel manager - directly relevant to the open Prison-load lost-fence hang); NRC SDK v0.14 -> v0.15 with a statically linked MSVC runtime, moving the companion DLL set to the CUDA 13 family (cudart64_13 / nvrtc64_130_0 / nvrtc-builtins64_133 - MUST deploy with the renderer or NRC fails init at level load); alpha-tested hair-card preservation (REMIX-2901, new rtx.hairCardTextures options); view-model flag through the Remix API (REMIX-5701); texture tagging restored for preserved instances (REMIX-5794); recompute-hash-on-write option (REMIX-5804); thin-opaque SSS transmission cutoff fix at grazing angles (REMIX-4451); TraceRay default on AMD Windows drivers; invalid render-target safety check (GH-1041). One conflict (rtx_options.h adjacency: upstream hairCard options vs PK particleTexturesExclude, both kept). All 58 PK commits replayed; rtxdi submodule stays on the BinqAdams MegaLights pin.
- Fix use-after-free in the light debug UI (upstream PR candidate): dynamicLightMatching erased churning dynamic lights from m_lights without holding m_lightUIMutex, and the m_linearizedLights pointer cache stayed stale between garbageCollection's unlock and the prepareSceneData rebuild, which itself mutated the vector unlocked - the light-overview tooltip on the present thread then dereferenced freed lights. Five c0000005 minidumps in PrimInstanceOwner::isRoot via drawToolTip (2026-07-17..07-26), all while hovering the light list to collect neverCullLights hashes. Every erase site now purges the cache (removeFromLinearizedLights), dynamicLightMatching takes the shared lock, and prepareSceneData holds it across the fallback-light reset and rebuild. `patches/Painkiller/findings/steam-rc7-bridge-crash/`.

## 0.3.9 RC6 - 2026-07-23  (pk-integration @ 2cee483d)
- `inputs:sprite_sheet_playback_mode` (new material attribute, Opaque + Translucent, default 0): per-instance spritesheet playback for regular replaced materials. 0 = legacy (global clock, all instances in phase, loops); 1 = play once from the instance's spawn and hold the last frame; 2 = loop phase-anchored to instance spawn. A spawn timestamp is stamped at RtInstance creation (same wrapped 24-bit-ms domain as cb.timeSinceStartSeconds, wrap-safe subtraction) and carried in spare Surface bits (data13.z bits 19-20 + previously-padding data15.w), and the frame formula in surface_interaction.slangh uses instance age with the particle-style min(lastFrame, ...) clamp for mode 1. Mirrors the RTX particle system's birth-relative OverrideMaterial_Lifetime behavior for game-drawn quads. Requires the draw to map to a stable instance (constant topology, drawn every frame, spacing above rtx.uniqueObjectDistance from same-material twins). RayPortal + animated-water paths unchanged. Authoring: `custom int inputs:sprite_sheet_playback_mode = 1` next to the existing sprite_sheet_rows/cols/fps on the material Shader over.
- SetConfigVariable("key", "") now clears the option's user-layer opinion (disableLayerValue) instead of being silently dropped: Config::findOption reports an empty-VALUED option as absent (config.h:328 value.length() > 0), so readOption early-returned and the write-only API had no working way to return a list option to empty - the HQ-blood OFF toggle was still one-way even after the assignment-semantics fix. Pairs with that fix as the upstream candidate: together they make runtime list-option updates fully symmetric (set, replace, clear).
- Hash-set/hash-vector option reads now have assignment semantics (rtx_option.cpp readValue): HashSetLayer::parseFromStrings only inserts, so a repeated read into the same layer value (the write-only Remix API SetConfigVariable) could only ever grow the set, and an empty value was a no-op instead of clearing - runtime toggles of texture-category lists were one-way (found via the HQ-blood toggle failing to switch back to particle blood). readValue now clears the layer set/vector before parsing. Upstream correctness fix candidate.
- `rtx.particleTexturesExclude` (new, default empty): texture hashes removed from particle categorization even when present in `rtx.particleTextures` (rtx_types.cpp setupCategoriesForTexture). Runtime-toggleable via the Remix API without rewriting the user-authored particle list (SetConfigVariable is write-only), same ownership pattern as `rtx.dlfg.suspendForMenu`. First use: the PK proxy's `[EngineHooks] HQBloodToggle` — the RTX-menu "High quality blood" option excludes the four blood spritesheet hashes so blood renders as full ray-traced geometry instead of particles.
- Rebased the PK fork onto NVIDIA dxvk-remix `main` 2647ebfd (+16 commits, from 80ddf69a): BLAS-pool update-type fix for flickering geometry when index topology changes (38aa605b), option to always use vertex-captured texcoords (REMIX-2810), external-presenter ImGui backend rework (separate output buffers, color-space fix, sub-window offset/scale), canonical Remix categories export for the Toolkit (REMIX-5725), volumetric composition fixes (secondary NRD disabled, DLSS-RR secondary volumetric). All 51 PK commits replayed clean; rtxdi submodule stays on the BinqAdams MegaLights pin; bridge untouched by the incoming range.
- `rtx.ignoreFixedFunctionTextureOpsOnReplacementMaterials` (new, default true): mesh replacements with an authored USD material no longer re-apply the ORIGINAL draw's captured fixed-function texture-stage ops (color/alpha ops + texture-factor blend) to the material output. Those ops rewrote the authored albedo/emissive/opacity in-shader (opaque_surface_material_interaction.slangh ~741: e.g. an untextured FFP draw's SELECTARG2(DIFFUSE) replaced albedo with vertex color wholesale) while normal/rough/metal, fetched outside that block, still applied — replacement materials appeared to partially not work. Found via the Leper thrown-blade replacements (blades draw untextured under ForceTnL, captured with a stale sky texture and empty UVs; their SelectArg2 stomped every authored albedo). Scoped to eMesh replacements with their own material; includeOriginal and texture-hash material replacements keep legacy ops. Flag: DrawCallState.usesReplacementMaterial (rtx_scene_manager.cpp drawReplacements) consumed in rtx_instance_manager.cpp updateInstance. Verified live via Debug View Diffuse Raw Albedo vs Diffuse Albedo. Upstream PR candidate. `patches/Painkiller/findings/blade-albedo/`.

## 0.3.8 RC5 - 2026-07-20  (pk-integration @ 7be26bc8)
- `rtx.distanceCullLights.neverCullLights` (new): comma-separated 0x-hex list of light initial-hashes exempt from distance culling and always kept, like `rtx.ignoreTextures` for lights. `lookupHash` early-return in `getDistanceFadeFactor` (rtx_light_manager.cpp:401). Read hashes from the dev-menu light overview; stable for USDA lights with absolute/world-space transforms. Combined with per-level cull distances -> fewer simultaneous lights -> less RTXDI noise.
- pinFullMips: decoupled mip-pinning from load scheduling in `preserveTexture`. `async` had been overloaded as the pin switch; a prior async flip (4d1ff9f4) dropped the pin + `requestMips(MAX_MIPS)`, so rasterized replacements with no sampler-feedback leader (sky/UI, dome light) sat at the lowest mip. New `pinFullMips` param pins + requests full mips independent of async; sky/UI/HUD/dome-light keep async (combat-hang fix preserved) while getting full res.
- Combat GPU-starvation hang fix: dome-light + RT-engaged sky replacement texture tracks flipped to async, removing a frame-thread `RtxIo::flush(wait=true)` that under heavy-combat VRAM pressure parked the cs thread on an unbounded GPU wait. Worst combat stall 195ms -> ~9ms, no hang across ~9700 frames. Rasterized-UI async gated on a valid 3D camera (async in gameplay, sync only on RT-disengaged 2D menu).
- Bridge rebuilt as the matched pair from the same tree (no IPC ABI change this cut).
- `patches/Painkiller/findings/{omm-vram-hang, rasterized-async-mip, light-nevercull}/`.

## 0.3.7 RC4 - 2026-07-14  (pk-integration @ 2611715c, rebased onto upstream main 80ddf69a)
- Rebased the PK fork onto NVIDIA dxvk-remix `main` (80ddf69a, +23 commits): merged BinqAdams PR 142 (`BlasEntry::m_linkedInstances` std::vector -> std::unordered_set, O(1) unlink), [REMIX-5644] don't preserve instances with material-driven particle effects, [REMIX-5660] preserve configured texture hashes on write lock, [REMIX-5119] point-instancer transform upload sync, [REMIX-5034] Alt+Tab ImGui input-state clear, struct-hash + bent-normal perf/correctness.
- Graph option-layer leak fixed: the bulk graph-instance teardown paths (`RtGraphBatch::removeAllInstances` and `RtxGraphManager::clear` -> default `~RtGraphBatch`) destroyed instances WITHOUT running each component's cleanup callback, while the per-instance `removeInstance` path did. `RtxOptionLayerAction` ref-counts an `RtxOptionManager` option layer per graph instance (initialize acquires, cleanup releases); on a level change the graph state is bulk-cleared, so the departed level's option layer was never released and stayed registered + frozen enabled. Per-level env-config layers accumulated across every visited level (confirmed in the Option Layers dev panel), and their equal-priority values fought (stale `enableFogRemap=True` from an earlier level leaking into a later one). Fix: run cleanup for all instances in `removeAllInstances` before dropping per-instance data, and route `clear()` through it. Upstream dxvk-remix bug; PR candidate. `patches/Painkiller/findings/env-conf-layer-leak/`.
- Particle ghost fix: particle systems (keyed by material+desc, shared across instances) are erased at `maxTtl` and re-created on the next emitter draw; every incarnation derived its synthetic-draw geometry hashes from the same seed, so `(numParticles, generation)` pairs recurred and, with `numFramesToKeepBLAS` retaining entries, a re-created system exact-matched a dead incarnation's cached `BlasEntry` and re-materialized its build-time vertex snapshot (leftover animated particles frozen at old spawn locations - picked-up electro-ammo positions in Painkiller). Fold the manager's monotonic per-incarnation creation counter into the draw-hash seed. Upstream bug; PR candidate. `patches/Painkiller/findings/electro-ammo-zombie-particles/`.
- First-menu FPS cap fixed: the boot-time `rtx.enableVsync` latch used a truthiness check on the D3D9 `PresentationInterval`, but `D3DPRESENT_INTERVAL_IMMEDIATE` is `0x80000000` (nonzero) and `DEFAULT` is `0` - inverted for the two common values, so the first menu latched vsync-on and capped at the refresh rate. Latch off only for IMMEDIATE. Upstream bug; PR candidate.
- Renderer + bridge remain a matched pair (bridge source unchanged this cycle, no IPC delta); PDBs shipped; Tracy renderer twin produced (dev only, not in the depot).

## 0.3.6 RC3 - 2026-07-06  (pk-integration @ 42bf5194)
- `rtx.materializationBudgetTrianglesPerFrame` (new, default 0/off; PK ships 500000) — per-frame bound on NEW-geometry materialization (upload + interleave + BLAS build). Over-budget draws are skipped statelessly and retried on following frames: original draws via the game's own resubmission, replacement prims via the new `ReplacementInstance::pendingMaterialization` pending-work flag, which bypasses the preserve path until every prim has materialized. Admission is under-budget-with-one-mesh-overshoot so a per-frame trickle of small new geometry (particles) cannot starve meshes larger than the budget. Kills the camera-rotation frame-spike burst (many culled entities' replacements re-materializing at once); evidence chain in `patches/Painkiller/findings/rotation-hitch/`.
- `rtx.logGeometryLifecycle` diagnostic (new, default off) — `[GeomLife]` log lines for BlasEntry / instance / replacement-instance creation and eviction with asset-rule hashes; used to identify which assets churn during camera motion.
- Ships with `rtx.numFramesToKeepBLAS = 3600` (geometry-data keep rides the same option — caches the expensive re-upload/BLAS-rebuild across cull gaps) and `numFramesToKeepInstances` at default 1 (2+ causes one-frame doubled additive particle quads = brightness pops).
- NRC restored: the `.trex` NRC/CUDA companion DLL set (NRC_Vulkan / cudart64_12 / nvrtc64_120_0 / nvrtc-builtins64_128) now ships matching the renderer's NRC SDK v0.14.1 pin — a renderer built after the NRC submodule bump against stale DLLs failed init at level load and silently fell back to Importance Sampled indirect.
- Bridge unchanged since 0.3.5 (same tree, no source delta); renderer + bridge remain a matched pair; PDBs shipped.

## 0.3.4 - 2026-06-24  (pk-integration @ 2e0339e8, rebased onto upstream main f3cf833a)
- DrawCallCache: pair world-space-bone skinned instances by a representative bone's world position (`rtx.assumeWorldSpaceSkinnedBones`, new, default off). The option also collapses skinned `objectToWorld` to identity (world placement lives in the bones). Object-space-bone games are unaffected (default off). Root cause + verification: `patches/Painkiller/findings/flicker-rootcause/SWARM-PAIRING-CENTROID.md`.
- Advanced the PK fork to NVIDIA dxvk-remix `main` (f3cf833a): picks up [REMIX-5501] particle-system stale-clump fix and [REMIX-5604] clear previous transform for newly preserved instances (motion-vector correctness on the preserve path).
